Contexto aprobado del Chat 02 para implementación de validaciones MongoDB
1. Modelo final de datos aprobado
Arquitectura general
Base de datos orientada a MongoDB.
Modelo híbrido:
Referencias mediante ObjectId para relaciones entre entidades.
Campos snapshot en registrosParqueo para conservar información histórica y optimizar consultas.
Convención de nombres: camelCase.
Identificadores principales: _id con tipo ObjectId.
Colección: sedes
Objetivo

Representar las diferentes ubicaciones físicas donde funciona el sistema de parqueaderos.

Documento
{
  "_id": "ObjectId",
  "nombre": "Sede Central",
  "direccion": "Zona 10, Ciudad de Guatemala",
  "capacidadTotal": 100,
  "estado": "ACTIVA"
}
Campos
Campo	Tipo BSON	Obligatorio	Descripción
_id	ObjectId	Sí	Identificador único generado por MongoDB.
nombre	String	Sí	Nombre identificador de la sede.
direccion	String	Sí	Ubicación física de la sede.
capacidadTotal	Int32	Sí	Capacidad máxima de la sede.
estado	String	Sí	Estado operativo de la sede.
Relaciones

Relación:

sedes 1 ─── N zonas

Una sede puede contener múltiples zonas.

Colección: zonas
Objetivo

Representar las divisiones internas de una sede donde se administran espacios de parqueo.

Documento
{
  "_id": "ObjectId",
  "sedeId": "ObjectId",
  "nombre": "Zona A",
  "tipoZona": "GENERAL",
  "capacidad": 30,
  "estado": "ACTIVA"
}
Campos
Campo	Tipo BSON	Obligatorio	Descripción
_id	ObjectId	Sí	Identificador único de la zona.
sedeId	ObjectId	Sí	Referencia a la sede perteneciente.
nombre	String	Sí	Nombre de la zona.
tipoZona	String	Sí	Clasificación de la zona.
capacidad	Int32	Sí	Cantidad máxima de vehículos permitidos.
estado	String	Sí	Estado operativo de la zona.
Relaciones

Referencia:

zonas.sedeId → sedes._id
Colección: usuarios
Objetivo

Almacenar las personas que interactúan con el sistema:

Administradores.
Empleados.
Clientes.
Documento
{
  "_id": "ObjectId",
  "nombreCompleto": "Juan Pérez",
  "documento": "123456789",
  "correo": "juan@email.com",
  "telefono": "55555555",
  "rol": "CLIENTE",
  "estado": "ACTIVO"
}
Campos
Campo	Tipo BSON	Obligatorio	Descripción
_id	ObjectId	Sí	Identificador único del usuario.
nombreCompleto	String	Sí	Nombre completo.
documento	String	Sí	Documento de identificación.
correo	String	Sí	Correo electrónico.
telefono	String	Sí	Número telefónico.
rol	String	Sí	Rol dentro del sistema.
estado	String	Sí	Estado del usuario.
Relaciones

Relación:

usuarios 1 ─── N vehiculos

Un usuario cliente puede tener varios vehículos.

Colección: vehiculos
Objetivo

Registrar los vehículos asociados a usuarios clientes.

Documento
{
  "_id": "ObjectId",
  "placa": "P123ABC",
  "tipoVehiculo": "AUTOMOVIL",
  "marca": "Toyota",
  "modelo": "Corolla",
  "color": "Blanco",
  "usuarioId": "ObjectId"
}
Campos
Campo	Tipo BSON	Obligatorio	Descripción
_id	ObjectId	Sí	Identificador único del vehículo.
placa	String	Sí	Identificación del vehículo.
tipoVehiculo	String	Sí	Tipo de vehículo.
marca	String	Sí	Marca del vehículo.
modelo	String	Sí	Modelo del vehículo.
color	String	Sí	Color del vehículo.
usuarioId	ObjectId	Sí	Referencia al propietario.
Relaciones

Referencia:

vehiculos.usuarioId → usuarios._id

Relación:

usuarios 1 ─── N vehiculos
Colección: registrosParqueo
Objetivo

Registrar los ingresos y salidas de vehículos dentro del sistema.

Representa la entidad transaccional principal.

Documento
{
  "_id": "ObjectId",

  "vehiculoId": "ObjectId",
  "placaSnapshot": "P123ABC",

  "usuarioId": "ObjectId",
  "clienteSnapshot": "Juan Pérez",

  "sedeId": "ObjectId",
  "sedeSnapshot": "Sede Central",

  "zonaId": "ObjectId",
  "zonaSnapshot": "Zona A",

  "fechaIngreso": "Date",
  "fechaSalida": "Date",

  "estado": "ACTIVO",

  "tarifaAplicada": "Decimal128",
  "totalPagado": "Decimal128"
}
Campos
Campo	Tipo BSON	Obligatorio	Descripción
_id	ObjectId	Sí	Identificador del registro.
vehiculoId	ObjectId	Sí	Referencia al vehículo.
placaSnapshot	String	Sí	Placa almacenada históricamente.
usuarioId	ObjectId	Sí	Referencia al cliente.
clienteSnapshot	String	Sí	Nombre histórico del cliente.
sedeId	ObjectId	Sí	Referencia a sede.
sedeSnapshot	String	Sí	Nombre histórico de sede.
zonaId	ObjectId	Sí	Referencia a zona.
zonaSnapshot	String	Sí	Nombre histórico de zona.
fechaIngreso	Date	Sí	Fecha y hora de entrada.
fechaSalida	Date	No	Fecha y hora de salida.
estado	String	Sí	Estado del parqueo.
tarifaAplicada	Decimal128	Sí	Tarifa aplicada al ingreso.
totalPagado	Decimal128	No	Total cobrado al finalizar.
Relaciones

Referencias:

vehiculoId → vehiculos._id

usuarioId → usuarios._id

sedeId → sedes._id

zonaId → zonas._id

Reglas de integridad
Las referencias deben utilizar ObjectId.
vehiculos.usuarioId debe apuntar a un usuario existente.
zonas.sedeId debe apuntar a una sede existente.
registrosParqueo debe mantener referencias válidas.
placa debe ser única.
documento debe ser único.
correo debe ser único.
correo debe tener formato válido.
telefono es obligatorio.
capacidadTotal debe ser mayor que cero.
capacidad de zona debe ser mayor que cero.
tarifaAplicada debe ser mayor que cero.
totalPagado debe ser mayor o igual a cero.
3. Decisiones técnicas importantes

Se utiliza:

camelCase

nombreCompleto

fechaIngreso

Identificadores

Todos los documentos utilizan:

Relaciones

Se implementan mediante referencias:

ObjectId

Embebidos

No existen documentos embebidos completos.

Fechas

Se utiliza:

Date

para:

fechaSalida
Valores monetarios

Se utiliza:

Decimal128

para evitar problemas de precisión.

Campos de auditoría

No se definieron campos adicionales como:

createdAt
updatedAt

porque no forman parte del alcance aprobado.
